# PRD: Notion CMS 포트폴리오 사이트

- 작성일: 2026-11-25
- 상태: 초안 (MVP 범위 확정 대기)

## 1. 개요

### 1.1 한 줄 요약
Notion 데이터베이스에서 프로젝트를 관리하고, 웹사이트는 Notion API로 데이터를 가져와 포트폴리오로 보여 준다.

### 1.2 배경 및 문제
- 포트폴리오를 수정할 때마다 코드를 고치고 배포해야 해서 번거롭다.
- Notion은 이미 프로젝트 정리에 쓰고 있으므로, 이를 단일 원본(Single Source of Truth)으로 삼으면 별도 DB와 관리자 페이지가 필요 없다.

### 1.3 목표
1. Notion에서 프로젝트를 추가·수정하면 코드 변경 없이 사이트에 반영된다.
2. 방문자(채용 담당자, 동료 개발자)가 1분 안에 작업물을 파악한다.
3. 30분~수 시간 내에 MVP를 만들 수 있는 단순한 구조를 유지한다.

### 1.4 비목표 (MVP 제외)
- 자체 관리자 페이지, 로그인/회원 기능
- 댓글, 방문자 통계, 다국어
- Notion 외 다른 CMS 지원

## 2. 사용자

| 구분 | 설명 | 핵심 니즈 |
|---|---|---|
| 방문자 | 채용 담당자, 동료, 클라이언트 | 프로젝트를 빠르게 훑고, 기술 스택과 링크를 확인 |
| 운영자(본인) | 사이트 소유자 | Notion만으로 콘텐츠 관리, 공개/비공개 제어 |

## 3. 핵심 사용자 시나리오
1. 방문자가 홈에서 소개와 대표 프로젝트를 본다.
2. 프로젝트 목록에서 기술 스택 태그로 필터링한다.
3. 카드를 눌러 상세 페이지에서 설명, 담당 역할, 데모/저장소 링크를 확인한다.
4. 운영자가 Notion에서 새 행을 추가하고 `공개`를 체크하면, 잠시 후 사이트에 노출된다.

## 4. 기능 요구사항

### 4.1 MVP (P0)
| ID | 기능 | 설명 |
|---|---|---|
| F1 | 홈 | 자기소개, 대표(Featured) 프로젝트 3개 이내 |
| F2 | 프로젝트 목록 | 카드 그리드(썸네일, 제목, 한 줄 설명, 기술 스택 태그) |
| F3 | 기술 스택 필터 | 태그 선택 시 목록 필터링 (클라이언트 상태는 Zustand) |
| F4 | 프로젝트 상세 | Notion 페이지 본문(블록)을 렌더링, 데모/저장소 링크 버튼 |
| F5 | 공개 제어 | Notion `공개` 체크된 항목만 노출 |
| F6 | 로딩/에러/빈 상태 | 스켈레톤, 오류 메시지, "프로젝트가 없습니다" 안내 |

### 4.2 확장 (P1)
- 정렬(최신순/직접 지정 순서), 검색
- 다크 모드
- SEO 메타데이터와 OG 이미지(썸네일 사용)
- Notion 변경 즉시 반영(Webhook 기반 재검증)

### 4.3 이후 (P2)
- 경력/학력 타임라인 DB
- 연락 폼, RSS

## 5. Notion 데이터베이스 설계

데이터베이스 이름: `Projects`

| 속성 | 타입 | 필수 | 용도 |
|---|---|---|---|
| 제목 | Title | O | 프로젝트명 |
| 슬러그 | Rich text | O | URL 경로 (`/projects/{slug}`) |
| 요약 | Rich text | O | 카드의 한 줄 설명 |
| 썸네일 | Files & media | | 카드/OG 이미지 |
| 기술 스택 | Multi-select | O | 필터용 태그 |
| 역할 | Rich text | | 담당 업무 |
| 기간 | Date (범위) | | 진행 기간 |
| 데모 URL | URL | | 배포 링크 |
| 저장소 URL | URL | | GitHub 등 |
| 대표 | Checkbox | | 홈 노출 여부 |
| 공개 | Checkbox | O | 사이트 노출 여부 |
| 순서 | Number | | 수동 정렬 |

페이지 본문은 상세 설명으로 사용한다. 지원 블록은 문단, 제목, 목록, 이미지, 코드, 인용, 구분선이다.

## 6. 기술 설계

### 6.1 아키텍처
```
[Notion DB] --Notion API--> [apps/api (Express)] --JSON--> [apps/web (Next.js)] --> 방문자
```
- Notion 토큰은 서버(API)에만 두고 브라우저에 노출하지 않는다.
- API는 응답을 메모리 캐시(예: 60초 TTL)로 감싸 Notion 호출 한도(평균 초당 3회)를 보호한다.

### 6.2 API (apps/api)
성공 응답은 `{ data }`, 실패 응답은 `{ error: { message, details? } }`.

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/projects` | 공개 프로젝트 목록. 쿼리: `tag`, `featured` |
| GET | `/api/projects/:slug` | 프로젝트 메타데이터 + 본문 블록 |
| GET | `/api/tags` | 사용 중인 기술 스택 태그 목록 |

- 입력(`tag`, `slug`)은 zod로 검증한다.
- 존재하지 않거나 비공개인 슬러그는 `HttpError(404)`를 던진다.
- 환경 변수 `NOTION_TOKEN`, `NOTION_DATABASE_ID`는 `src/config/env.ts`에 추가한다.
- 라우터는 `src/routes/index.ts`에 등록한다.

### 6.3 웹 (apps/web)
| 경로 | 페이지 |
|---|---|
| `/` | 홈 |
| `/projects` | 프로젝트 목록 + 필터 |
| `/projects/[slug]` | 프로젝트 상세 |

- 서버 데이터는 TanStack Query, 필터 선택 상태는 `src/stores/`의 Zustand로 관리한다.
- API 호출은 `src/lib/api.ts`의 `api()` 래퍼를 사용한다.
- 헤더 메뉴는 `header.tsx`의 `links` 배열에 `프로젝트`를 추가한다.
- UI 문구는 한국어로 작성한다.
- 컴포넌트: shadcn/ui `card`, `badge`, `skeleton`, `button`(링크는 `buttonVariants`) 등.

### 6.4 데이터 모델 (TypeScript)
```ts
type Project = {
  id: string;
  slug: string;
  title: string;
  summary: string;
  thumbnail?: string;
  techStack: string[];
  role?: string;
  period?: { start: string; end?: string };
  demoUrl?: string;
  repoUrl?: string;
  featured: boolean;
};
```

## 7. 비기능 요구사항
- **성능**: 목록 첫 로딩 LCP 2.5초 이내. Notion 이미지 URL은 만료(약 1시간)되므로 서버에서 캐시하거나 프록시하는 방안을 검토한다.
- **보안**: Notion 토큰은 `.env`에만 두고 커밋하지 않는다. helmet, CORS 설정을 유지한다.
- **반응형**: 모바일 우선. 카드 그리드는 1/2/3열로 전환한다.
- **접근성**: 이미지 대체 텍스트, 키보드 탐색, 충분한 명도 대비.
- **신뢰성**: Notion API 장애 시 마지막 캐시를 반환하고, 캐시도 없으면 오류 안내를 표시한다.

## 8. 성공 지표
- Notion 수정 후 사이트 반영까지 최대 1~2분 이내 (MVP는 캐시 TTL 기준)
- 코드 수정 없이 프로젝트 추가/숨김이 가능하다.
- `npm run typecheck`, `lint`, `build` 통과

## 10. 리스크 및 대응
| 리스크 | 대응 |
|---|---|
| Notion API 호출 한도 | 서버 캐시, 목록 호출 최소화 |
| 이미지 URL 만료 | 서버 프록시 또는 응답 시점에 URL 갱신 |
| 블록 타입 다양성 | MVP는 지원 블록만 렌더링, 미지원 블록은 건너뜀 |
